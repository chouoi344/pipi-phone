# 屁屁机：已确认目标与初版边界

> 2026-11-15维护说明：下文保留原有产品要求。当前源码基于用户0.5.0原包，版本0.11.0，已实现角色引擎第0至6步；新增与修改要求以工作区 `最新内容/角色引擎方案.md` 和 `项目交接.md` 为准。模型选择、内置模块、金额规则、时区等冲突项按新方案执行。本文正文中的旧版实现与验证状态属于历史资料；当前功能和验证入口见 [0.11.0角色引擎说明](ENGINE-0.11.md)，[0.5.1第0步记录](ENGINE-STEP0.md)仍保留。

## 产品原则

首次进入从启动画面起就使用微信经典版。「我 → 皮肤」提供微信经典版和原图纯净水滴，选择保存在当前浏览器。页面切换、功能按钮和弹窗共用交互逻辑。水滴是整机外观，涵盖首页与底部导航、聊天、朋友圈、服务、好友配置、模型设置和弹窗。水滴版的默认聊天壁纸是「晴空樱花」，好友自选背景优先。水滴版根据实际收发进度呈现等待、正在输入和新消息入场。

2026-11-19 用户选定第三版预览中的「经典」为整机外观。浅灰聊天底色、白绿气泡、系统中文字体、消息列表、好友信息及配置沿用获选样式。转账保留蜜桃水晶卡片，红包采用珊瑚色与封口图形，展示实际领取、收款或退还状态。自选好友壁纸仍在该会话内生效。

经典版聊天、好友配置及转账共用左上返回箭头。转账填写页用浅灰背景、白色金额栏和键盘，输入有效金额后绿色按钮可用。聊天「＋」第一页提供语音转文字，点完成把文字放进草稿。好友八类配置的图标和名称在同一列居中。独立按钮的点击范围按至少 44×44 CSS 像素设计；通讯录字母按连续拖动选择，右侧滑动区宽 44 像素。

2026-11-22 消息防抖按好友收集连发，新默认停顿 2.5 秒，安静窗口结束后才判断一次；新消息使该好友旧判断失效。已有生效参数保留，明确旧格式继续按上版读为停顿 1 秒、半句 3 秒、最长 8 秒，原始备份不改。整轮最长仍为 8 秒，更短的已保存上限保留；到点直接回复已发消息并停止旧判断，固定停顿方式不调用判断模型。可在「发现 → 功能 → 消息防抖 → 专业微调 → 停顿缓冲（秒）」改成 3 秒或其他小数。生成中追加消息会重新组织回答，已完成的待发动作保留且只投递一次。本轮证据在工作区 `.codex/validation/global-audit-20261122/debounce/`，均为隔离程序和本机模拟模型。

开源、不售卖程序；每位使用者一台服务器、一套实例、一个账号。苹果和安卓统一采用 iPhone 微信风格。核心是界面还原、流畅操作和 AI 角色交流。第一阶段原生风格且实际可用，第二阶段再做美化。

## 运行环境与字体（2026-11-14 补充）

程序部署在服务器，用户从手机浏览器进入网页使用；以后可能制作连接同一服务器的 App。后续布局、字体、资源加载及安全区处理都要以这个实际运行方式为前提，不能只按本机桌面预览判断。

用户希望接近 iPhone 默认字体的观感，并要求替代字体免费可商用。0.5.0 起：苹果设备直接使用系统字体（即微信原生所用的苹方与 SF），其他设备使用随网页自托管的 Inter（西文）与 Noto Sans SC（中文），只在需要时才下载。未来若 App 使用网页容器可沿用；若采用原生界面，须在其工程中另行配置字体。字体文件和 OFL 许可证一并保留，不分发苹果专有字体。

开发每个模块前优先查询 Git 仓库；符合需求且许可明确的现成组件优先复用。常规实现和资料核对优先使用 gpt-6.1-sol；用户已允许根据任务复杂度使用 gpt-6-astra，适用于复杂的跨页面审查及独立对抗性验证，思考深度按任务安排。交付前必须独立做对抗性验证。

## 界面还原的优先级（本轮重做约束）

- 第一步先完成整个仿微信的 UI 与交互还原，第二步才做美化；不得用自创布局替换微信的页面结构。
- 真实 iPhone 微信是最终参照；用户提供的安卓模拟器是已认可的参考水平，不能因平台差异忽略该样板。
- 已锁定用户当前版本为 **iPhone 微信 8.0.80**。外观以用户提供的原生截图为优先证据；同版本公开素材也必须核对具体界面，不能将旧 iOS 开源实现或安卓模拟器的尺寸、控件轮廓直接当成 8.0.80 的规范。
- 各区域逐控件审查：原生实际长什么样、证据来自哪里、当前是否对齐、不同输入/选中状态是否一致。SVG 外框尺寸或功能测试通过不等于图形轮廓一致；原生高像素密度图应与同密度网页截图对照。
- 还原覆盖字体、字重、图标、间距、分隔线、气泡、菜单位置、页面层级、进入返回、长按、左滑及键盘交互。功能测试通过不能作为视觉达标结论。
- 模型、角色设定、用户人设、记忆、主动活动等 AI 管理入口集中在“我 → 设置”；主聊天页、通讯录和朋友圈不放常驻 AI 管理控件。
- 聊天信息页、好友资料页、好友更多设置页分别保留原生层级；不能把聊天右上角“…”直接跳到角色管理表单。
- 对不确定的参考应提供具体界面给用户判断，不以项目名、星数或作者自称高仿作为还原证明。本轮用户已授权按上述目标重做，完成后再验收。
- 2026-11-14 的真实微信截图作为聊天底栏与表情面板的新基准：约半屏展开，顶部搜索/表情/收藏/自拍分类、最近使用、七列纵向滚动、右下删除与发送；不用旧版三行分页替代。原生截图仅内部对照，私人内容不进入源码和发布包。
- 电脑预览外围使用有对比的灰色底、细边框和上下留白，使手机界面四边清晰；手机端维持满屏。该调整已获用户认可，后续精修应保留。
- 顶部系统状态区域、底部手势区域由设备系统提供。真实手机网页按浏览器实际安全区避让，包含二级页面、全屏编辑器和弹层；任何平台都不绘制时间、信号、电池或底部手势条。桌面手机预览在没有设备安全区时模拟顶部 47px、底部 34px 的预留位置，以保留用户要求的图三布局，同时保留外围对比背景与细边框；该模拟值不叠加到真实手机安全区。键盘、旋转与视口变化不能丢草稿或遮挡按钮。
- 聊天输入框中点选的表情应直接显示表情图片，内部仍可用标签保存/发送；文本与表情混排、光标插入、整枚删除、中文输入法和草稿恢复必须可用。
- 页面导航按真实用途区分：进入子页面后用返回箭头返回上一级；放弃编辑或退出选择的独立流程保留取消。不能让通用弹层模板把所有页面左侧都默认为取消，也不能把所有取消机械改成返回。

## 已确认业务目标

- 微信、通讯录、发现、我四主页面，已确认功能的相关子页完整。
- 好友全部为 AI。角色人设与用户人设分开，可创建多份用户人设并绑定给不同好友；关系、记忆独立。
- 模型两入口：预设提供商只需密钥且有默认模型；自定义提供商填 URL/密钥。文字、识图、语音、生图可分别配置。
- 真实模型对话、微信式消息节奏。长期记忆可查看改删；参考插件后续讨论。
- 双向语音消息。实时语音通话后续可选。生图具体用途与插件后续讨论。
- 朋友圈可以发布、点赞、评论，与聊天关联；角色默认互不知情，详细规则后续完善。
- 网页在前台时，其他好友的新消息在顶部提醒，点开可进入对应聊天。当前对话和免打扰的好友遵循各自的提醒设置。关闭网页后，服务器仍按角色开关、频率及时间段主动活动。
- 虚拟钱包有余额和流水；农场金币独立；现实账本独立。
- 农场种植、成熟、收获、访问好友农场与简单互助。
- 现实记账手动或识图成草稿，必须用户确认后入账。默认角色不可读取，只知道用户主动分享的内容。
- 服务端持久数据与整套业务备份恢复，支持服务器迁移。

## 展示与后续

群聊、扫一扫先展示后续开通；拍摄、视频通话、位置、礼物、个人名片发送、文件、卡券、音乐、公众号、服务号等只展示，点击提示未开放。其他无关原生业务子页不纳入首期。

## 本次初版的明确边界

- 没有收到真实 API 密钥。接口协议使用隔离的本地模拟服务验证，不声称已通过用户实际提供商测试。
- 预设提供商的 URL/默认模型未提供，因此先支持部署者设置预设；不会编造一个服务地址。
- 可编辑的明确记忆是基础功能。自动记忆抽取/检索和生图插件未定，不伪装为已接入。
- 初始示例角色/消息必须标为示例；它们不是 AI 生成结果。主动活动默认关闭，用户配置后开启。
- 初版农场数值和虚拟初始余额是可调整演示规则，不是用户已定稿的经济系统。
- 业务备份包含应用数据与媒体，不含密码、登录会话和 API 密钥。迁移后重新设置登录与密钥。
- 对抗性验证应区分 API 自动测试、源码检查、浏览器实测和未覆盖的真实手机/外部服务场景。

# iPhone 微信 8.0.80 界面复查

本轮版本：0.4.2。日期：2026-11-14。

## 本轮：首页比例、适配、状态与支付

新增原图为用户提供的 945×2048 首页截图，带红色标注。以宽度归一到 390px 后高度约为 845.2px；红框不属于 UI，不能当成控件边缘。原图包括 iOS 系统状态区和底部安全区，网页只根据设备实际 `safe-area-inset-*` 留白，不绘制假的时间、信号或 Home 指示条，也不在电脑上强行增加 34px 底部空白。

| 区域 | 本轮发现与修正 | 验证边界 |
| --- | --- | --- |
| 首页顶部 | 标题字号 18px、标题栏最小 48px；搜索白框最小 38px，文字 18px。放大镜按实际可见轮廓调整到约 17px，标题加号约 21px。旧搜索字和图形偏小，加剧了紧凑感。 | 系统状态区与标题栏边界未在原图独立标明，48px 为与原图相容的布局选择，不冒充唯一原生值。 |

| “我”的状态 | 在微信号下方添加独立状态入口；选择、编辑、展示、修改、取消和结束完整贯通，随账号保存；后端验证描述、过期和备份恢复。改正超长描述后及时清除旧长度错误，保留网络和保存错误。 | 状态页使用公开旧版 iOS 结构参考与现有许可图标，14 种选项、60 字和 24 小时为当前产品规则，未声称所有 8.0.80 状态能力已实现。 |

| 转账详情 | 聊天卡片不再直接进入带内部账单编号的通用流水表；改为转账图标、实际虚拟发送状态、金额、说明、对象和时间。 | 不伪造已收款、待收款、退款或真实支付验证。 |

| 支付窄屏与长文字 | 专项覆盖 320×568 竖屏、844×390 触屏横屏及左右 47px/底部 21px 模拟安全区，检查 60 字对象名和备注、滚动后命中按钮、说明弹窗及详情全文换行。 | 首次溢出读数确认来自现有 180ms 进入动画的第一帧；等待动画完成后原断言通过，没有用隐藏溢出来掩盖布局问题，也没有把动画过渡当成稳定页面失败。 |

最终完整浏览器回归 **42/42 通过**，无浏览器异常；后端隔离对抗性测试 **30/30 通过**。16 项产品及测试文件在最终浏览器执行前后哈希一致；此前已接受的聊天输入栏、表情区另做图像回归。首次全套发现搜索用例清空输入与中文组合输入之间的测试准备竞态，固定准备阶段后保留原节点稳定性断言并在完整套中通过；另一次执行进程中断没有计为通过。

已部署到原预览地址 `http://127.0.0.1:18768/`，版本 0.4.2，使用原数据卷。停服后完成逐文件校验的离线备份；升级前后业务 JSON 原始哈希、密码指纹及 2 个登录会话保持一致。8 个前端资源逐字节匹配最终源码。最初的只读卷数据库审计无法打开 WAL 数据库时已自动恢复旧预览，随后改用备份的临时副本审计，未在原数据卷写入审计文件。

详细执行结果见 [浏览器验证](UI-VERIFICATION.md) 与 [后台对抗性验证](ADVERSARIAL-RESULTS.md)。首页原图的逐项测量见 [首页审查](NATIVE-ROOT-042-AUDIT.md)，支付和状态的实际来源与限制分别见 [支付审查](PAYMENTS-VISUAL-REVIEW.md)、[状态审查](STATUS-REVIEW.md)。

## 保留并回归的 0.4.1 修正

之前的偏差主要来自参照混用、只看控件外框而没有核对实际图形，以及输入状态覆盖不足。现在以用户提供的原生截图为直接基准；旧版 GitHub 项目和安卓模拟器只提供实现参考，不作为 iPhone 8.0.80 的外观证明。

原图直接覆盖的是单聊、空输入框、展开全部表情的状态。复查使用独立浏览器、390×844 视口和 3 倍像素截图，测试资料均为虚构内容，没有复制原图中的私人头像、名称和消息。下表把“有原图支持的修正”和“尚缺原生对照的区域”分开记录。

| 区域 | 怀疑性问题 | 本轮核查结论 |
| --- | --- | --- |
| 聊天标题 | 字号、字距真的接近原图吗？ | 原图中文步长约 17.9px，聊天标题改为 18px；其它页面标题不据此推定。 |
| 正文与头像 | 文字看着小、头像与气泡挤在一起了吗？ | 正文改为 18px，头像 43px，头像到气泡约 13px；六字与四字短气泡分别约 134px、98px。 |
| 气泡尾巴 | 方向相同就算还原了吗？ | 对照实际尖端和中心，修正尾巴偏高约 3px、伸出过长约 1px的问题。 |
| 最后一条消息 | 展开面板后是否立即完整可见？ | 修复沿用旧滚动位置导致末条消息被挡的问题；可见输入行与末泡间距约 12.9px，原图约 12.8px。 |
| 历史阅读 | 修正贴底会不会把历史消息强行拉到底？ | 独立验证真实滚轮翻历史后，切换面板和输入多行文字仍保留阅读位置。 |
| 输入框 | 宽高正确，圆角和内边距也正确吗？ | 保留已接近的 249×42px 空框，圆角调为 4px；逐个核对内部与外部按钮的位置。 |
| 输入框内麦克风 | 是原图的普通麦克风，还是混进了别的样式？ | 去掉多余横足，调整胶囊、U 形与短竖杆；最终可见尺寸约 13.3×18px，接近原图 13.6×18.2px。 |
| 左侧语音、键盘、加号 | 图标画布相同，实际轮廓也相同吗？ | 按实际圆形和内部图案检查；不把 SVG 的外框宽度当作图案宽度。 |
| 表情分类栏 | 搜索、笑脸、爱心、自拍是否整体偏右？ | 修正约 8px 的横向偏移；四个中心约为 31、85、139、193px，并校正搜索、爱心大小。 |
| 表情标题和最近使用 | 是标题、图案还是整块间距有偏差？ | 分区标题改为 15px；只移动需要修正的最近使用标题与表情，保留全部表情标题的布局位置。 |
| 全部表情网格 | 面板达到半屏，就代表内部节奏一致了吗？ | 逐行对照七列和行距，修正标题到首行多出的空隙；最终首行图案中心约 669.8px，原图约 670.2px。 |
| 删除与发送 | 按钮能点，内部符号和底部留白也对了吗？ | 校正底部位置、删除符号与发送字号；删除可见轮廓约 21×16.3px，原图约 21.1×16.5px。 |
| 右下操作区 | 原图没有露出的表情，当前是否仍从按钮旁露出来？ | 补齐整块灰色保留区域，并验证被覆盖表情不能误点；320px 等五种视口中第四列仍可正常选择。 |
| 中文与多行输入 | 首字、候选、换行、面板切换会不会重建输入框？ | 修复首字组合输入残留拼音；保持输入节点，验证多行、光标、表情切换与中文搜索。原生 iOS 键盘外观仍需实机对照。 |

| 聊天列表、通讯录 | 行距、分组、右侧字母栏、状态标记合理吗？ | 补齐可操作字母索引，移除“已隐藏会话”内部标记，验证搜索与导航；精确原生行尺寸仍缺同版本对照。 |
| 发现、我、资料、聊天信息 | 层级正确是否等于每一行都还原？ | 已检查实际页面和返回层级；未取得原生逐页截图的字体、分隔线、开关等，不标为像素验收完成。 |
| 朋友圈、相册、评论 | 功能可用是否能代替视觉对照？ | 已做路由、作者过滤和评论交互回归；这些原生页面的精确排版仍需对应参考。 |
| 红包、转账、钱包 | 金额正确、卡片可见就等于原生页面吗？ | 验证金额、卡片完整可见、详情与返回；保留虚拟账务语义。没有同版本原图的数字字形、卡片和表单细节不冒充已验证。 |
| 更多功能与录音状态 | 旧版参考的顺序和录音动画还能直接套用吗？ | 已查现有入口与交互；更多面板顺序、原生录音动画及未展示的输入状态仍列为待对照项。 |
| 电脑外围与手机边缘 | 页面是否再次和背景混在一起？ | 保留已接受的灰色外围、细边框、上下间距；小屏保持铺满，并检查横向溢出。 |

最终完整浏览器回归 **36/36 通过**，无浏览器异常；后台隔离对抗性测试 **26/26 通过**。浏览器回归覆盖五种尺寸，最终使用的 14 个源码及测试文件在执行前后哈希一致。先前发现的中文输入、转写与组合输入并发、面板打开时消息遮挡均保留了失败与修复记录。

这些结果证明本轮已列出的具体问题完成修复，并不证明没有原图的页面已与真实微信完全一致；Windows 字体渲染也不能等同于 iPhone 实机。详细测量见 [独立视觉审查](IOS-8080-AUDIT.md)，执行记录与限制见 [浏览器验证](UI-VERIFICATION.md) 和 [后台对抗性验证](ADVERSARIAL-RESULTS.md)。

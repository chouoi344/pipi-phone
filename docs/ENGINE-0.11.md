# 0.11.4 角色引擎使用与维护

2026-11-15。0.11.4承接既有角色引擎，并按本轮用户决定暂时撤下主动消息和时间间隔提示，后续单独讨论；定时提醒与自动朋友圈保留。引擎在Node.js 24中独立运行，零npm运行依赖；功能随版本内置，不下载或安装插件。协议为AGPL-3.0-only，原有许可条目保留。

## 从哪里开始

“我 → 设置 → 小手机”包含模型和时区；功能、用量单独放在设置首页的“小手机”分组。正常预览继续使用原数据，不导入验证资料。

2026-11-16 模型配置增量已接入：自己的站位于顶部；其他服务商在模型列表上方。提供对话、语音转文字、文字转语音、生成图片、判断、嵌入、重排序七类。对话选择1～4个，其中一个为当前聊天模型；其他类别各选1个。已选对话列表与原备用模型顺序独立，切换或取消选择不删除旧模型及参数。

添加服务商时预填已核实的官方地址和图标，允许修改地址；API Key留空保留已有密钥。先保存服务商，再获取模型清单或手动填写模型ID；勾选后点完成。BreezeBlue位于文字转语音分类。原有模型参数、备用模型、整理/转述用途仍可通过高级设置维护。

“屁屁自己的站”使用四组独立密钥。部署地址由环境变量 `PIPI_SOURCE_URL`、`PIPI_VOICE_SOURCE_URL`、`PIPI_IMAGE_SOURCE_URL`、`PIPI_AUXILIARY_SOURCE_URL` 配置；七类默认模型分别由 `PIPI_CHAT_MODEL`、`PIPI_STT_MODEL`、`PIPI_TTS_MODEL`、`PIPI_IMAGE_MODEL`、`PIPI_DECISION_MODEL`、`PIPI_EMBEDDING_MODEL`、`PIPI_RERANK_MODEL` 配置。地址或默认模型缺失时，一键配置禁用。配置完整后自动创建缺少的模型，保留已有模型及用途选择；不内置假地址或密钥。

本轮完成配置页面、保存与兼容，不代表七类执行能力都已实现：原有OpenAI兼容调用保持；BreezeBlue/MiniMax/Qwen原生语音、判断和重排序调用尚未适配，发起执行会返回明确错误。图片和嵌入的实际业务功能仍待后续接入。BreezeBlue支持读取原生模型清单；MiniMax/Qwen原生语音先手动填模型ID。未发送真实付费模型请求。

朋友圈“提醒谁看”与可见范围同步：私密时隐藏，公开或自选范围时显示；只允许提醒可见朋友。确认收紧可见范围会移除不符合范围的提醒，取消修改保持原选择及正文草稿。

## 好友人设与身份

“我 → 我的人设”管理 AI 好友设定：分别填写名称与正文，直接输入、粘贴或上传 TXT（1MB 内、正文不超过10万字符）。TXT 先进入草稿，预览并保存后生效；已有正文时替换前确认。支持 UTF-8、带 BOM 的 UTF-16 和 GB18030 中文编码。

列表按可用宽度显示一列或两列卡片。默认没有文件夹，需要时从右上角新建；通过卡片三点菜单编辑、绑定朋友、移动分类或删除。每个朋友使用一份人设，同一份可绑定多个朋友。更新正文后，对应朋友的后续模型请求使用新内容。

原来用于描述“你是谁”的人设保留在“我的身份”，与好友人设分别保存。已有好友的独立设定也保留：绑定库中人设后优先使用所选内容，解除或删除绑定后继续使用原独立设定。创建好友的基础表单不强制人设绑定和模型选择，已有模型配置保持。

添加/编辑朋友时可填写“拍一拍”，聊天中双击朋友头像会在实际消息里显示该内容；单击继续打开资料。自己的拍一拍仍使用个人资料中的设置。

自己和好友的朋友圈封面分别保存。进入“通讯录 → 好友 → 朋友圈”，点封面后选择“更换相册封面”即可为这位好友换图，保存后重新打开仍保留。

## 聊天和角色动作

发送后输入框可继续用，默认停笔3秒后生成，距最后已发消息最多等待30秒；草稿不会自动发送。生成或分段中插话会取消未发内容，已经送达的内容保留。生成中标题显示“对方正在输入…”。整份回复超过150字只发一条；其他回复默认最多6条，节奏在“功能”调整。

长对话自动整理。摘要不出现在普通状态或界面里，也不替代可编辑的共同记忆；它随备份保存，清空会话或删除好友会同步移除。没有识图能力的聊天模型可使用图片转述；无可用识图模型时会明确告诉角色看不到图片。角色能读到本会话的红包/转账状态、拍一拍、语音文字、引用、撤回和当前时间；现实账本不提供给角色。时间间隔提示已撤下，不再追加“距上一条消息过了……”提示。

支持动作的模型可以发红包/转账、领取或退还、拍一拍、引用用户消息、撤回自己的两分钟内消息、发布及互动可见朋友圈、安排提醒。角色表情在“角色管理 → 好友 → TA 的表情库”添加；发语音需要配置语音合成用途。动作是否发生由模型决定，不把“支持”当成每次必做。

好友初始1000元虚拟零钱，升级时给已有好友一次性补发。红包默认上限200元，红包和转账每日各5次，按统一时区分日；余额不能透支。用户发给好友的款项等待角色领取或退还；好友发来的款项由用户打开卡片领取。待处理满24小时自动退回；删除好友会退回用户尚未被领取的转出款。金额、次数和时长可在“功能 → 角色动作”调整，金额单位为分。

## 提醒和参数

可以让好友安排一次性、每天、每周或间隔提醒，默认每好友最多20个未完成提醒、重复间隔至少1小时。“聊天 → 右上角… → TA 的提醒”可查看和删除。任务保存到服务器，重启后保留；迟到1小时内补发，超过则作废或顺延到下一次。

用户要求的提醒照常穿过免打扰；角色自行安排的提醒推迟到免打扰结束。首次登录自动取浏览器时区，可手动更改；聊天时间、提醒、免打扰、用量分日和每日次数都按它计算。服务器需要运行；本版没有系统推送，消息须打开小手机查看。自动朋友圈仍按原有设置运行。

“功能”按模块声明自动生成参数表单。长对话整理、图片转述、分段回复、等待与打断、角色动作、定时提醒始终内置。主动消息和时间间隔提示已从设置入口及运行流程撤下，旧开关即使为开启状态也不再触发；其参数格式和旧数据仅为备份兼容保留。维护者在 `lib/engine/modules/` 增加声明并在Registry（功能登记入口）登记，参数、钩子、动作、定时工作和模块数据由统一入口处理。

## 0.11.2界面调整

“新的朋友”右上三点只作显示，创建后回到已添加好友列表。好友基础资料可直接上传朋友圈背景图。“我 → 朋友圈”增加相册/状态页与个人朋友圈入口；发布的可见范围和提醒对象从底部打开选择页，支持现有联系人标签。四项为公开、私密、部分可见、不给谁看；后两项按发表时的朋友名单保存，后续新加朋友不会自动看到这些旧动态。个人页“发表”预选公开，“私密发表”预选私密；原有普通相机入口仍保持私密默认。自己的收藏表情与好友表情库均支持一次多选上传；好友表情可逐张编辑名字后整批保存。

## 0.11.3界面修复

红包页点击金额才打开数键盘，祝福语使用设备键盘，笑脸加号打开收藏表情；表情随红包记录保存。通讯录仅调整已有图标。新填或更改微信号时禁止中文，旧值和备份保留。朋友圈可见范围、联系人、标签、提醒页修正图标行宽与箭头对齐，权限规则保持。发表页的位置及下方两行文字按基线对齐。

# 使用说明与功能细节

[返回项目首页](../README.md)

首次进入小手机默认使用微信经典版。在「我 → 皮肤」可预览「原图纯净水滴」，点卡片右下角的「激活」输入与安装编号对应的激活码。激活后，在同一套小手机上登录的设备都可以切换两套皮肤，每个浏览器记住自己的选择。水滴版按置顶状态把会话分在上下两张卡里，空组自动收起。默认聊天壁纸为「晴空樱花」，好友的自选壁纸优先，可在「聊天信息 → 设置当前聊天背景」里更换或恢复默认。点聊天里的转账或红包可查看收付状态。

保留原数据目录可延续激活。将业务备份导入另一套独立安装时，请用新的安装编号联系皮肤提供者获取激活码。

**0.13.0** 增加聊天媒体保存期限、流式备份、账号与安全和三种作息。旧资料会在启动时自动整理，继续支持导入旧版备份。[升级说明](../升级说明_0.13.0.md) · [更新记录](../CHANGELOG.md)

一个自己部署、自己使用的微信风格 AI 角色聊天网页。每台服务器一套实例，手机或电脑登录同一个后台；业务数据保存在服务器的 SQLite 中。

打开任一好友聊天，从「聊天信息 → TA 的提醒下方 → 角色配置」进入八个分类。基础配置保存好友音色和城市，照片保存三视图及可选全身图，衣柜与日程、相册、朋友圈共享该好友的资料。我的表情库负责上传和标注，好友从库中选择可用表情。全局动作开关在「发现 → 功能」。

已归档的共同记忆可从「角色配置 → 记忆 → 已归档」查看、编辑或手动恢复。聊天再次提到归档内容时会标出「最近聊到过」；遗忘还会从用户画像中清理相关条目。

满 72 小时未收到用户发给该好友的消息时，暂停生成新日程。用户再次开口后恢复。主动私聊按好友选择跟随日程或自己配置。没有当天日程时，私聊使用该好友的自定义参数。睡眠中的普通定时私聊醒后最多补一次，用户指定的准点提醒照常触发。自动发圈有独立开关，按日程判断时机。角色朋友圈每页由服务器返回最多 4 条。

模型页的七个分类使用同一套服务商卡片。分类标题右侧可添加服务商，选好类型后在原位填写名称、接口地址和 API Key，再获取模型列表或自定义型号。每个模型在小弹窗确认后加入当前卡片，可以连续添加多个。卡片底部统一保存服务商和模型，空密钥默认保留同一地址的已保存密钥。
两个窗口同时修改同一服务商的 API Key 时，后保存的一方会看到密钥变更提示。取消会保留草稿，点确认才会写入本次密钥。一键配置也按分组检查；需要确认时整批暂缓保存。

已配置的模型可启用、停用、编辑和移除。停用时保留参数和用途选择，恢复启用后可继续使用。「小手机 → 对话设置」可手动选择对话主模型、回退顺序、图片转述模型和语音模型。添加模型后，主对话和图片转述由用户选择。语音转文字和语音条理解在「模型 → 语音转文字」中设置。

已知对话型号自动勾选能力，未知型号默认全开并可手动调整。上下文容量为 0 时按型号自动识别，正数沿用手填容量。可手动配置请求参数、超时和适用分类的调用方式。连接测试由模型右侧的插头触发，结果显示模型名及耗时，生成图片分类省去测试按钮。音色沿用好友设置。

同页保存、查询或数据更新会保持滚动位置和设置区展开状态；主动切换内容分类时从顶部显示。

模型超时在模型弹窗的「更多参数」里设置。新模型留空时按接口取默认值。常用兼容对话为 120 秒，MiMo 转写为 20 秒，兼容 Whisper 转写为 600 秒，常用语音合成为 20 秒，MiniMax 合成为 60 秒，兼容嵌入和重排序为 20 秒，判断为 5 秒。千问 Omni 音频理解、Breeze 和生成图片沿用 45 秒。判断的日常调用和连接测试共用模型超时，语音或图片下载链接也用对应模型的秒数，每次请求独立计时。已有的自定义秒数继续生效。

真机反馈版更新了聊天转场、按压反馈、表情面板和新消息提示。模型重试超过 30 秒可从聊天标题栏取消。生图时可以继续发消息，成图会先于角色的发送确认到达。聊天里长按表情可以收藏，朗读时可点气泡旁的喇叭停止。角色配置、模型和小手机设置采用通栏分组。

上下文先按轮数上限裁剪，再判断是否需要总结；总结失败时继续移除最早的完整轮次，保留当前轮。当前轮连同工具结果仍超过估算容量时，原文交给模型处理，上游拒绝会正常报错。裁剪仅影响本次模型输入，已有聊天记录保留。

聊天临时故障会限次重试，耗尽后按已有回退模型顺序切换；空回复最多3次，网络、超时、限流和服务端临时错误最多5次，鉴权与参数错误直接报告，取消后停止。总结仍只请求一次。工具调用和结果保存在所属好友的聊天历史中，后续回复可读取；随整轮一起裁剪，删除或清空对应聊天时清理。服务重启中断了分段回复时，可点击原消息的重试按钮继续接收未送达片段，不重复已发内容、模型请求或已执行动作。

“我 → 设置 → 用量与日志”集中查看累计用量和简洁调用记录。默认总用量，可选今天、7天、15天、一个月（近30天），趋势固定显示近一周。逐条日志保留90天，清理明细不会减少累计；旧版已清理的历史无法补回。日志支持搜索、状态/用途筛选与详情，新调用保存耗时和安全失败原因，旧记录缺失的信息标为未记录。

语音模型已拆分为“录完后转文字”和“语音条理解”，分别选择模型；支持 MiMo ASR 和千问 Omni，语音条的原话、内容情绪和声音情绪分别提供给角色。模型调用方式可在参数中选择，官方服务地址与自定义中转地址独立保存，详见安装说明。2026-11-17通过choupi.tech各一次4.015秒合成录音实测，两个型号均准确转写，Omni返回独立的内容/声音情绪；官方直连与真人麦克风效果尚未实测。

长期记忆、日程与穿搭、语音、自拍、日常联系和角色工具从「发现 → 功能」进入。用量从设置首页打开，好友人设在「我 → 我的人设」维护和绑定。安装及升级见[安装说明](../INSTALL.zh-CN.md)。本版的测试、实机步骤和已知性能限制见[审查报告](../审查报告_v0.13.0.md)。

独立的“自主活动”页面和自动任务已停用，旧备份里的计划与作息记录可随原资料恢复。主动信息与自动发圈按好友设置运行。旧[0.12角色引擎说明](ENGINE-0.12.md)、[0.11说明](ENGINE-0.11.md)和[0.5.1记录](ENGINE-STEP0.md)保留作历史参考。

时间、信号、电池与底部手势条由用户设备系统显示，网页不额外绘制。无触屏的鼠标电脑预览在实际安全区为零时保留顶部 47px、底部 34px 空位；真实移动端按浏览器实际 `safe-area-inset-*` 避让，实际为零时不再补电脑占位。安全区动态变化会自动更新；键盘仅压缩可视区域时调整底边，转账说明弹窗跟随可视区域居中。浏览器已经避让的系统区域不重复留白；模拟检查不能代替真机验证。

安全区原有实现记录见 [SAFEAREA-044.md](SAFEAREA-044.md)；它与 [CONTROL-REVIEW-043.md](CONTROL-REVIEW-043.md)、[UI-VERIFICATION.md](UI-VERIFICATION.md) 均为历史记录，参考与许可见 [REFERENCE-043.md](REFERENCE-043.md)。原生截图直接覆盖首页、聊天与空输入表情面板；旧版开源代码、公开旧版页面和安卓模拟器仅作实现参考，不能证明未提供截图的页面与 8.0.80 像素一致。

## 在 Docker 中启动

需要已运行的 Docker 和 Docker Compose。在本目录执行：

```sh
docker compose up -d --build
```

本机打开 **http://127.0.0.1:18766/**。首次使用时填写名字，并设置至少 8 个字符的登录密码，再次输入确认即可。

容器内使用 Node.js 24，数据保存在 `pipi-data` 命名卷中。镜像不包含个人记录、登录密码或 API Key。普通重启和重新构建保留数据；不要使用 `docker compose down -v`，该操作会删除数据卷。

常用操作：

```sh
docker compose ps
docker compose logs --tail 100 pipi-phone
docker compose restart pipi-phone
docker compose stop
```

## Ubuntu 服务器部署

把本目录上传到已经装好 Docker 的 Ubuntu 服务器，使用上面的 Compose 命令即可运行。应用和开发机使用同一套 Linux 容器；不依赖 Windows 路径。

默认端口仅绑定服务器本机。可以先在自己的电脑建立 SSH 隧道，然后访问电脑上的 `http://127.0.0.1:18766/`：

```sh
ssh -N -L 18766:127.0.0.1:18766 ubuntu@你的服务器地址
```

正式供手机跨网络访问时，在前面配置 HTTPS 反向代理，并在 Compose 的 `environment` 中添加自己的域名与安全 Cookie 配置：

```yaml
ALLOWED_HOSTS: phone.example.com
COOKIE_SECURE: "1"
```

将示例域名替换为自己的域名。代理需要保留原始 `Host`，网页和 API 使用同一域名。默认只在服务器的 `127.0.0.1` 上发布端口。需要指定其他宿主机监听地址时，通过同目录 `.env` 设置 `PIPI_HOST_BIND`。本次交付不包含域名、证书或公网部署。

## 直接在本机运行

需要 Node.js 24 或更新版本，无需安装 npm 依赖。Windows 双击 `start.cmd`，或执行：

```sh
node server.cjs
```

默认地址仍为 `http://127.0.0.1:18766/`，数据位于本目录的 `data/`。同一时间只能有一个程序占用该端口。

## 第一次体验

1. 初始化账号，在“我”中修改个人资料。首次安装时，通讯录和聊天记录为空，可以从聊天首页点“创建新朋友”。
2. 打开「我 → 设置 → 小手机 → 模型 → 屁屁自己的站」，填入需要接入的分组 API Key，点底部「一键配置」。对话分组保存密钥，随后到对话服务商卡片获取模型列表、选择并保存。语音、画图和辅助分组自动添加默认模型，补齐空缺的用途选择。既有模型参数和用途选择继续生效。
3. 在同一张卡片直接用当前填写的地址和密钥获取列表，也可以手动添加型号。点型号确认加入后，用卡片底部的「保存」统一提交。模型右侧齿轮可查看参数。到「小手机 → 对话设置」选择主模型、回退顺序、图片转述模型和语音模型。好友的音色在「角色配置 → 基础配置」里选择。实际接口支持范围见 [0.12.0 说明](ENGINE-0.12.md)。
4. 在“通讯录 → 新的朋友”添加好友，从好友资料编辑基础信息；“我 → 我的人设”管理 AI 好友人设与绑定。旧版角色资料保留，所有好友使用全局对话模型。
5. 在“发现 → 功能”调整聊天节奏和工具调用，在“我 → 设置 → 小手机 → 时区”确认时间。首次登录自动取浏览器时区。未配置模型时，发送消息会显示配置错误并可重试。

API Key 保存在服务器的数据库中，普通状态接口只显示是否已配置。当前导出 TAR 备份，默认包含模型 API Key 与图片、语音，可在导出前取消相应选项。含密钥的备份未加密，请妥善保管。

农场初始100金币、10个共用种子；胡萝卜5分钟成熟得20金币，番茄10分钟成熟得35金币，收获返还2个种子；原有农场每日互助按UTC日期计算。农场金币、虚拟钱包和现实账本相互独立。用户虚拟零钱初始1000元；好友初始发放、红包上限和每日次数可在“功能 → 角色动作”调整，金额参数单位为分。

好友表情库从用户图库多选添加，按图片去重；聊天发送不自动扩充好友图库，普通照片不收藏。发送给模型的图片、表情包有独立类型标记，引用、转发和转述保留类型。用户图库支持批量上传 PNG、JPG/JPEG、WebP、GIF、BMP、AVIF；静态图自动压缩，最长边按1024像素处理；压缩结果更小时才替换，BMP/AVIF转成兼容格式。GIF/APNG/动态WebP保留原动画。用户图库及每位好友的表情库各最多200张，Base64图片按实际字节计入16MB总容量。移除好友表情不删除用户图库原图。

用户表情库点击图片可查看、编辑含义、语气标签与适用场景；画面描述及原字只供AI读取，角色配置不展示标注。上传后使用已配置的图片转述模型生成标注；未配置保留待识别，失败可重试。相同图片共用结果，人工修改优先；角色按语义检索自己已选的表情，找不到合适内容可不发。动图由支持ImageDecoder的浏览器抽取最多5帧，无法解析时允许手填；分析帧保存到服务器媒体目录。AI识图会产生所配置渠道的费用，本机开发旧图库10张已直接看图人工补标，无外部模型请求。

语义流程参考 [astrbot_plugin_meme_manager 5.4.1](https://github.com/anka-afk/astrbot_plugin_meme_manager/tree/1561b4fdb8669f6579da61565f4aadc5d3080723)（MIT），独立实现；未引入插件运行时、向量数据库或npm运行依赖。

语音与生图动作分别需要配置语音合成、生成图片模型；模型未勾选“角色动作”能力时只会聊天。群聊、扫一扫、视频通话、强提醒等仍未开放。好友来信在网页前台可显示顶部横幅，安卓 App 可使用系统消息通知。记忆检索可使用已配置的 embedding 与 rerank 模型。

新动作使用执行记录防止重试重复发送；重启后的未知结果不自动重做。每次模型请求按当前模型容量检查，超出容量明确报错；正文、摘要、图片转述和计划备注过滤内部推理标签，保留工具协议需要的 metadata。

## 备份与迁移

在「我 → 设置 → 关于屁屁机 → 网页程序更新」更新服务器上的小手机。安卓 App 从 0.1.3 起在同一页另设「安卓 App 更新」，点它可以从自己的服务器更新手机上的 App。Docker Compose 部署首次开启服务器更新、发布与回退的步骤见[网页更新说明](WEB-UPDATE.zh-CN.md)。

通过「我 → 设置 → 聊天记录管理」导出 `.tar`。默认包含 API 密钥、图片和语音，选项可取消。可以恢复新版 `.tar` 或 88 MB 以内的旧 `.json`。导入会替换当前业务资料，目标实例继续使用自己的登录密码与会话。模型密钥只会还原到匹配的服务商和地址。含密钥的备份请自己保管。

SQLite 保存业务状态，主资料上限为 64 MB，聊天消息上限为 50,000 条。图片和语音保存在数据目录的 `media/`，媒体总量取决于服务器剩余空间。聊天媒体默认保存 7 天，可以在「我 → 设置 → 存储空间」修改。升级前备份和目录要求见[升级说明](../升级说明_0.13.0.md)。

## 验证

以下命令在带有 `tests/` 和 `compose.test.yaml` 的开发工作区运行。安装包可按首次安装步骤直接验收。

优先在 Linux 容器中运行隔离测试：

```sh
docker compose -f compose.test.yaml run --rm tests
```

测试容器关闭外网，仅使用容器自己的回环网络；源码只读挂载，临时数据库位于 `/tmp`，不会改动实际业务数据卷。

本机 Node 备用方式：

```sh
node --test tests/*.test.cjs
```

测试使用临时数据库与本地模拟模型服务，不调用付费接口。默认拒绝连接私网或本机模型地址；测试仅在隔离进程中明确开启本地模拟服务访问。

当前版本的验证范围、真机步骤和已知性能限制见[0.13.0审查报告](../审查报告_v0.13.0.md)。历史版本的说明保留在对应文档中。

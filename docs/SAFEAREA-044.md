# 0.4.4 系统栏与安全区验证

2026-11-14 需求重新确认：去掉时间、信号、电池及底部横条图形，同时保留系统区域应有的空间；电脑预览也应显示上下空位。先前“所有平台 inset 为零都取消占位”的规则已修正。

`public/phone-frame.js` 读取隐藏探针的四边 padding，将有效值传到 `.phone-shell` 的 `--safe-*` 属性。仅在无触屏能力、精细鼠标且支持悬停、实际四边全零时，作为电脑预览补顶部 47px、底部 34px；触屏设备保留真实浏览器值，包括零。任一实际边非零时采用整组实际值。整个过程不创建系统图标或底部横杠。

探针用 `ResizeObserver` 观察含 padding 的 border-box，CSS 安全区变化即使未引发窗口 resize 也可刷新。键盘检测结合可编辑焦点、未缩放的 VisualViewport 与页面高度差；明确压缩时只清除底边，保留顶部/左右值及短暂失焦状态。转账说明原生 dialog 根据可见区域及安全区居中限高，不再固定按完整布局视口居中。

根页底栏、聊天输入栏各自处理底部 inset；普通叶子页面由 `phone-frame-leaf` 处理；功能页、状态编辑器使用自身内容 padding。完整编辑器的安全区 padding 在外层，内部 feature-page 不再叠加底部 inset。朋友圈封面延伸至顶部，操作栏避开顶部与横向 inset；评论栏根据 shell 与 VisualViewport 位置定位。照片关闭按钮、底部操作表、警告框有相应避让规则。

顶部“+”菜单使用 `calc(8px + var(--safe-right))` 并限制宽度。本次浏览器模拟横屏左右各 47px、底部 21px，实测菜单位于有效范围内。准备的 `tests/frame043-scenarios.cjs` 同步更新了电脑 47/34、移动实际零值的期望。
